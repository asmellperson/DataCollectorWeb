# DataCollector Web

面向计算机视觉训练的数据采集、自动预标、人工审核和数据集导出平台。支持 `raw`、`classification`、`detection` 三类数据集。图片目录、视频和 RTSP 采集结果统一进入 JSON 标注与审核流程；安检视频工作区提供连续原视频、大模型时序初标、人工复核及本地训练清单。

## 功能

- 数据集创建、改名、类别管理、统计和删除；类别 ID 保持稳定，已删除的 ID 不复用，被标注引用的类别不可删除。
- 浏览器整目录上传（单次最多 10000 个文件）和服务器目录递归导入。支持 JPG、JPEG、PNG、BMP、WebP。图片复制到数据集内，不引用外部图片路径。
- 上传 MP4、AVI、MKV 或填写服务器视频路径，按每 N 帧或每 N 秒抽帧，可同时自动预标。
- 摄像头增删改、连接测试、实时预览；FFmpeg、TCP 优先、低缓冲、读流超时和断流重连。
- 四种采集模式：`raw_interval`、`roi_interval`、`detect_raw`、`detect_crop`；触发目标和自动标注类别独立选择，支持目标名称 / 模型类别 ID、独立的触发与标注模型；pHash 比较最近 128 张已保存图片。
- YOLO-World、自定义 YOLO；缓存模型，跨任务串行设置类别和推理，避免不同数据集类别串用。
- react-konva 原图画布：新增、选择、拖动、缩放、删除框、改类别、撤销；JSON 和带框预览同步保存。
- 图像分类使用类别按钮；raw 不需要标签。三种任务均可确认、拒绝、删除样本和导出。
- 图片导入、预标、视频、导出和连接测试均提供后台任务状态和取消操作。

## 架构与目录

```text
React / TypeScript / Vite
        ↓ /api（生产静态服务同源代理；开发时为 Vite）
FastAPI → 服务层 → SQLite 索引 + 文件系统
                ↘ 任务线程池
                ↘ 摄像头读流线程 → 模型管理器 → 样本保存

DataCollectorWeb/
├── backend/
│   ├── app/
│   │   ├── api/          数据集、标注、摄像头、采集、模型、视频、任务、导出
│   │   ├── services/     数据持久化、后台任务和采集业务
│   │   ├── inference/    Detector、YOLO-World、自定义 YOLO、模型缓存
│   │   ├── db/           SQLAlchemy / SQLite
│   │   ├── schemas/      请求参数和标注校验
│   │   ├── core/         配置、数据集锁、原子写入
│   │   └── main.py
│   ├── requirements.txt
│   └── run.py
├── frontend/src/         采集、图片审核、统计与安检时序标注等页面及组件
├── security_scan_dataset_tool/ 原桌面标注工具及复用的标签读取模块
├── datasets/
├── models/               模型权重与 CLIP 缓存
├── config/               index.sqlite3、配置和上传临时目录
├── start.sh              一键启动前后端
└── README.md
```

仅使用一个后端进程（`workers=1`）。摄像头读取与模型推理解耦；同一摄像头的预览和采集复用最新帧。全局最多同时运行 9 路 RTSP 采集，允许多个摄像头写入同一个数据集。每路独立任务、ROI、预览、计数和停止控制，同一摄像头同时只能运行一路采集。采集使用独立的 9 线程执行池，不占用普通任务线程；数据集写入仍串行提交，导入、预标、导出和删除等操作与该数据集的采集互斥。模型推理仍按模型管理器锁串行执行，实际检测速度取决于模型和硬件。

每个数据集：

```text
datasets/{id}/
├── dataset.json
├── images/               无框训练原图
├── annotations/          每张图片的权威 JSON
├── previews/             独立带框预览
└── exports/              导出目录与 ZIP
```

SQLite 只保存数据集、样本、摄像头、任务与状态索引，不保存图片二进制或完整标注。bbox 为原始图片像素坐标 `[x1,y1,x2,y2]`；裁剪图的框转换到裁剪图坐标，来源记录原图尺寸和裁剪区域。标注记录置信度及 `manual / yolo_world / custom_yolo` 来源。分类保存在 `classification.class_id/class_name`。

## 环境创建和依赖安装

在另一台服务器从内网仓库拉取、安装和启动，请参照[服务器部署说明](docs/deployment.md)。

安检视频标注还需要服务器提供 `ffmpeg` 和 `ffprobe`。它们用于原码流录制、逐帧时间索引和 H.264 播放副本；Python 和前端不增加第三方依赖。

需要 Python 3.11、Node.js 20+、npm。当前服务器环境名称：`data_collector_web`。

```bash
conda create -n data_collector_web python=3.11 pip -y
conda activate data_collector_web
cd /usr/zyy/DataCollectorWeb/backend

# 当前服务器使用 CPU；先安装 CPU 版 PyTorch，避免下载不需要的 CUDA 包。
pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt

cd ../frontend
npm install
```

GPU 主机需先安装与驱动相适配的 PyTorch。将 `config/example.env` 复制为 `config/.env`，设置：

```dotenv
DEVICE=cuda:0
```

CPU 使用 `DEVICE=cpu`，也是默认值。环境变量优先于 `config/.env`。支持 `WORLD_MODEL` 指定 YOLO-World 权重，`DATA_ROOT` 和 `STATE_ROOT` 指定新项目数据和索引路径。不要把它们设置到旧项目目录。

## 模型权重

默认 YOLO-World：`models/yolov8s-worldv2.pt`。当前服务器已下载该权重和 CLIP ViT-B/32 文本编码权重；另提供 models/yolov8n.pt 作为自定义 YOLO 选择示例。

在其他服务器安装时：

```bash
cd /usr/zyy/DataCollectorWeb
curl -fL -o models/yolov8s-worldv2.pt \
  https://github.com/ultralytics/assets/releases/download/v8.3.0/yolov8s-worldv2.pt
```

YOLO-World 使用 Ultralytics 官方接口，类别来自目标数据集，建议使用清晰的英文目标名称，例如 `person`、`helmet`、`forklift`。首次设置类别需要 CLIP，依赖已包含在 requirements 中；首次运行可能需要联网下载文本权重。模型每个 provider/路径仅加载一次，类别变化通过 `set_classes()` 更新。

参考：[YOLO-World 官方文档](https://docs.ultralytics.com/models/yolo-world/)。

## 启动

一条命令在后台启动前后端，无需手动激活 conda 环境：

```bash
bash /usr/zyy/DataCollectorWeb/start.sh
```

脚本自动查找 `data_collector_web` 环境，检查依赖和端口，等待前后端就绪后返回命令行。**可以关闭终端、断开 SSH 或关闭 VS Code，服务继续运行。** 后台进程使用独立会话，日志写入文件。

管理命令：

```bash
bash /usr/zyy/DataCollectorWeb/start.sh status   # 查看进程和健康状态
bash /usr/zyy/DataCollectorWeb/start.sh stop     # 停止前后端
bash /usr/zyy/DataCollectorWeb/start.sh restart  # 重启并加载代码更新
bash /usr/zyy/DataCollectorWeb/start.sh logs     # 持续查看日志，Ctrl+C 只退出日志查看
```

直接执行 `start.sh` 等同于 `start.sh start`。重复启动只显示现有实例；启停命令通过文件锁串行执行，并核验进程身份，避免过期 PID 导致误停其他进程。停止会等待当前任务退出，最多等待 45 秒后提示检查状态，不强制打断文件写入。如果某个服务异常退出，后台守护进程会停止另一个服务，查看日志后使用 `restart` 恢复。依赖首次安装请参照上面的安装步骤；脚本不会自动安装依赖。

日志保存在 `config/logs/backend.log`、`config/logs/frontend.log` 和 `config/logs/supervisor.log`，按启动次数追加。也可以直接查看：

```bash
tail -f /usr/zyy/DataCollectorWeb/config/logs/backend.log /usr/zyy/DataCollectorWeb/config/logs/frontend.log
```

只检查环境、不启动服务：`bash /usr/zyy/DataCollectorWeb/start.sh --check`。若 conda 环境安装在自定义路径，可通过 `DCW_PYTHON=/绝对路径/bin/python bash /usr/zyy/DataCollectorWeb/start.sh` 指定解释器。若端口被其他方式启动的进程占用，脚本会报错退出，不会自动结束其他进程。升级前已运行的旧版前台脚本需先在原终端按 Ctrl+C 停止，再使用新脚本启动。

网页和 API 统一使用 `5180`，服务器只需开放这一个端口。健康检查：`http://服务器IP:5180/api/health`；API 文档：`http://服务器IP:5180/docs`。后端通过项目内的 Unix socket `config/run/backend.sock` 与前端通信，不监听 TCP 端口。

当前服务器访问地址：**http://172.16.19.215:5180/**。启动脚本先构建生产资源，再通过 `frontend/server.mjs` 提供静态文件，并经本机 socket 转发 API 和接口文档请求，无需配置跨域；JS/CSS 启用 gzip，带哈希的资源长期缓存，HTML 重新校验。构建失败时不会停止现有服务。开发调试仍可在停止生产前端后执行 `npm run dev` 使用 Vite，开发代理也使用同一个本机 socket。

构建检查：

```bash
cd /usr/zyy/DataCollectorWeb/frontend
npm test
npm run build
```

平台当前面向可信内网使用，未实现登录、多用户权限或公网部署。后台启动不包含开机自启；服务器重启后，再次执行 `start.sh`。

## 安检视频自动标注与人工复核

侧栏“安检视频标注”使用独立的视频工作区，流程为：**连续原视频 → `fuda-qwen38-27b` 自动初标 → 人工复核 → 服务器本地训练清单**。无需先人工分割受检人，也不需要预先完成整段人工标注。

### 视频来源与存储

- 服务器已有录像：填写服务器文件路径，后台将原文件完整复制入库并计算 SHA-256，不修改源文件。支持 MP4、AVI、MKV、MOV、TS、M4V。
- 摄像头连续录制：选择已有摄像头，FFmpeg 将视频原码流直接保存为 MKV，不经过预览最新帧队列，不裁剪、画框或主动降低录制帧率。录制从点击开始持续到停止；应在人员进入前开始，保留动作发生前的画面。关闭页面不停止录制。
- 停止后建立源帧 PTS 时间索引，并生成 H.264 / YUV420P 浏览器播放副本。逐帧按钮读取原视频帧；训练清单引用原文件。时间戳重复、倒退、缺失或解码失败会明确报错；可检测的时间戳缺口记录在录像元数据中。
- 断流会结束当前录像并保留原文件，显示失败原因；可“重新准备已保存的原文件”检查已有内容，不把断流前后自动拼成正常轮次。当前连续录制每次产生一个原文件，适合先进行少量录像验证。
- 录制前会实际测试录像目录写入，分别提示权限、只读、空间或配额问题。RTSP 超时参数按已安装 FFmpeg 的能力选择，兼容旧版 `-stimeout` 和新版 `-timeout`。录制失败会显示 FFmpeg 的退出码及具体错误；最近的错误保存在该录像目录的 `ffmpeg.log`，摄像头地址经过脱敏。

工作目录位于 `${DATA_ROOT}/_security_inspection/`：

```text
_security_inspection/
├── recordings/{id}/
│   ├── recording.json       来源、哈希、准备状态与任务
│   ├── original.*           完整原视频
│   ├── preview.mp4          浏览器播放副本
│   ├── timeline.json        每帧源时间戳及缺口
│   ├── annotation.json      当前标注版本
│   ├── revisions/           已保存修订历史
│   ├── drafts/{run_id}/     预标参数、逐窗口采样帧号与模型响应
│   └── latest_draft.json    最近一次完整预标结果
└── exports/{id}/            train.jsonl、val.jsonl、snapshot.json、manifest.json
```

### 大模型初标

服务端直接调用已有千问服务的 `/chat/completions`，向模型提供按时间排序的原视频采样帧、全局帧号、源时间戳及前窗相关草稿。模型提出人物与角色、每位受检人的轮次、安检有无、动作及起止时间；不生成合规结论，也不根据速度直接判定未安检。

默认每窗 6 秒、重叠 2 秒、采样 12 FPS；页面可调整窗口、重叠、采样帧率和动作提示。动作提示为可修改的观察范围，九部位不作为固定完成要求。采样密度只影响模型输入，不能保证短动作一定被看清，无法判断的内容保留 `uncertain`。

跨窗仅按模型明确复用的人物与轮次 ID 续接，并检查受检人、时间范围和原有事件；不按时间相邻自动合并人员。新受检人使用新轮次，跨窗人物不确定时保留候选供人工修正。模型输出格式错误、截断或证据帧无效时任务失败，已收到的窗口响应保留，人工内容不被覆盖。

首次初标完成且人工版本仍为空时，草稿自动进入待复核。已有内容或推理期间发生人工保存时，新模型结果只保存为独立草稿；需要替换时使用“载入最近模型草稿”。

千问设置通过服务器环境或 `config/.env` 提供：

```dotenv
DATA_ROOT=/data/DataCollectorWeb/datasets
STATE_ROOT=/data/DataCollectorWeb/state
INSPECTION_VLM_BASE_URL=http://127.0.0.1:18100/v1
INSPECTION_VLM_MODEL=fuda-qwen38-27b
INSPECTION_VLM_TIMEOUT_SEC=120
INSPECTION_VLM_MAX_TOKENS=8192
```

认证可使用 `INSPECTION_VLM_API_KEY`，未配置时沿用 `SECURITY_VLM_API_KEY`；密钥不进入前端、标注或训练清单。模型服务需独立运行。

### 人工复核与已有工具复用

复核页沿用 `security_scan_dataset_tool` 的逐帧查看、起止标记、两层标注与同类区间冲突校验，并支持：

- 修正人物角色、衣着描述及当前证据帧的人物位置；每轮关联受检人和安检员，动作可指定执行人。
- 补充漏轮、在当前帧拆轮、合并下一轮、补改动作及时间范围。拆轮后的新轮次不继承原受检人；不同明确受检人的轮次须先修正人物关联才能合并。
- 分开保存 `inspection=present/absent/uncertain`、画面可用性、边界是否确定与人工审核状态。可以保存待确认结果；样本不可用不等于不合规。
- 时间使用原视频首帧为零点的秒数，区间左闭右开。“当前帧末设为结束”取下一帧时间戳，最后一帧取录像结束时间。
- 人工保存使用版本校验和原子 JSON，修订历史保留；保存响应丢失时先回读验证，避免重复提交。复核耗时按页面可见时的近期操作累计，超过 60 秒无操作不继续计时，用于试标耗时比较。

“读取原手动工具的已有标注”直接复用其 `LabelStore`、`EventStore` 和 `label_schema`，不加载 Qt。填写原数据目录和 `clip_id` 后先核对原视频哈希，再将旧版包含两端的帧区间转换为源 PTS 的右开秒区间；导入内容进入待复核，并补充人物关联。原工具仍可独立使用。

### 本地训练清单

在录像列表勾选数据，点击“在服务器生成清单”。只收录人工已确认、可用、受检人明确、轮次边界确定且安检有无明确的轮次。待确认、未审核、已排除或不可用内容不会转成训练负样本；动作边界不确定的事件不进入训练事件列表。

`train.jsonl/val.jsonl` 引用服务器原视频和时间索引，并内嵌固定版本的轮次、动作和人物标签；`snapshot.json` 保留完整复核快照。后续修改标注不会改变已经生成的训练标签。设置验证比例时按采集分组与相同原文件哈希共同分组，防止相邻片段或重复入库分到训练/验证两边；至少需要两组独立录像，单组可选择“仅生成训练清单”。连续录像被手动拆成多个文件时，应填相同“采集分组”。

代码通过 Git 同步到训练服务器；视频、标注、清单和后续训练产物保存在 `/data`，训练直接读取本地路径。清单不打 ZIP、不要求浏览器下载，也不传回开发机。训练框架、动作标准、顺序规则及合规判断尚未固化，先用少量连续录像验证初标质量与人工修正耗时。

API 前缀为 `/api/security-annotations`，包括 `GET /config`、`GET /recordings`、`POST /recordings/import`、`POST /capture`、`POST /recordings/{id}/stop`、录像及时间索引读取、`POST /recordings/{id}/prelabel`、`PUT /recordings/{id}/annotation`、`POST /recordings/{id}/apply-draft`、`POST /recordings/{id}/legacy-import` 与 `POST /manifests`。预标和视频准备复用平台后台任务状态及取消接口。

## 创建数据集

在“数据集”页点“新建数据集”，选择任务类型。detection 和 classification 至少提供一个类别，每行 `ID 名称`：

```text
0 person
1 helmet
2 forklift
```

raw 不填类别。ID 不会按名称重排；新增类别请使用未用过的 ID。在数据集列表的 **“类别 / 设置”** 中增加一行即可新增类别，也可改名、删除未被引用的类别。这些是数据集自己的 ID，不必与 COCO 或模型 ID 一致。训练单类别或任意多个类别时，在导出窗口勾选即可，无需删除原有类别。数据集删除有二次确认，不能删除正在执行任务的数据集。

新建弹窗提供 **“导入数据（可选）”**：

- 不选择目录，点击“创建数据集”，得到空数据集。
- 点击“选择本地图片目录”，显示目录名、图片数和大小；点击 **“创建并导入”**，先创建数据集，再自动上传和保存图片，无需跳转到采集页。
- 同一个弹窗持续显示 **“已导入 X / N 张”**、处理进度条、上传进度以及成功、失败、剩余张数。完成后可关闭或直接进入标注审核。停止导入会保留已创建的数据集和已保存图片。
- detection 数据集选好目录后，还可选择导入时使用 YOLO-World 或自定义 YOLO 自动标注。

## 数据集统计

在数据集列表点击 **“数据统计”**，或从侧栏进入并选择数据集。支持全部状态、仅已确认、仅待审核、仅已拒绝；默认全部状态包含已拒绝图片。统计按当前保存的 JSON 标注和图片索引生成，不修改数据。

- 总览：图片数、可读取标注数、有效框数、有标签图片数、已覆盖 / 已配置类别数、审核状态、每图框数均值 / 中位数 / 最大值。
- 类别表：原始类别 ID 与名称、框数、去重图片数、框占比、图片覆盖率、含该类图片的平均框数、单图最多框数、各审核状态图片数，以及小 / 中 / 大目标数量。配置中零标注类别仍显示；类别不重新编号。
- 分布图：类别图片数与框数、每图框数、目标大小、图片分辨率 / 横竖图 / 格式、采集来源与标注来源。目标大小按框面积占图片面积划分为小于 1%、1% 至不足 10%、至少 10%。
- 质量检查：已入库图片与标注缺失、JSON 格式异常、索引信息不一致、未知类别、非法 / 越界 / 零面积框，以及疑似重复、极小、细长框。未知类别和非法坐标不计入有效标注；疑似问题仅提醒，保留计数，不自动删除。
- 点击类别图片数、分布图或问题数量，可以筛选图片，搜索文件名 / ID，并跳转到该图片的标注审核。文件或标注结构异常的图片显示修复提示。支持导出类别统计和异常明细 CSV，附带统计范围与时间。

同图同类别只计一张图片，不同类别分别计数，因此类别图片数之和可能超过图片总数。目标检测中，“已确认无目标”只包括 approved 且空标注的图片；待审核空标注、无法读取标注、只有无效框的图片不会被视为已确认无目标。raw 和 classification 不显示目标检测框统计。

显示的是扫描时的统计结果；修改标注后点击 **“刷新统计”**。图片文件检查仅核对已入库原图是否存在，图片尺寸取自导入索引，不做图片解码、相似图检测或漏标判定。训练 / 验证 / 测试划分在导出时生成，不属于当前原始数据集统计。

API：`GET /api/datasets/{id}/statistics`，可选 `status=approved|pending|rejected`；不传表示全部状态。返回总览、类别、分布、质量检查和用于图片筛选的轻量明细，同一次请求来自同一数据集快照。

## 图片目录导入

图片目录导入统一放在 **“数据集”** 页面。新数据集在创建时选择本地目录；已有数据集点击对应行的 **“导入图片”** 补充图片。“数据采集”页面只提供视频抽帧和 RTSP 采集。

- 本地目录：点击“选择图片目录”，先显示图片数、总大小和自适应预览；选好设置后再点击“开始导入”。保留相对路径作为来源信息，大目录按最多 50 张或约 32 MB 分批上传（超出上限的单张图片单独一批）。
- 服务器目录：点击“服务器图片目录”，填写如 `/data/images/test`，递归扫描在后台执行，不经过浏览器传输。
- detection 数据集：在 **“导入时自动标注”** 选择 **“YOLO-World 自动标注”** 或自定义 YOLO，再勾选 **“自动标注类别”**（单选、多选或全选）。新建并导入、已有数据集补充导入均支持。每张图会完成推理、原图保存和 JSON 标注后更新处理进度，结果进入待审核。
- 已有 YOLO 检测标签：选择 **“图片 + 标签”**，分别选择本地图片目录和 TXT 标签目录。类别默认按每行 `编号 名称` 手动填写，也可选择 **“读取 YAML”**（支持 `names` 列表或编号字典，YAML 非必填）。新建数据集使用这些类别；已有数据集按名称匹配，可展开 **“类别对应”** 手动调整。
- 点击 **“检查文件”** 查看匹配、空标签、缺失标签和错误，再开始导入。按两个目录内的相对路径及同名文件配对，保留子目录；同一位置的同名不同扩展名图片会提示冲突。TXT 每行须为 `class_id x_center y_center width height`，坐标归一化到 0–1，空 TXT 表示无目标，缺失 TXT 的图片按未标注导入。类别未定义或框坐标非法时阻止导入。
- 带标签导入保留原框并进入待审核，可继续修改和导出。默认自动标注跳过已导入标签（包括空标签），勾选覆盖后才重新标注。单个 TXT 最大 2 MB，全部 TXT 最大 32 MB；超过时分批选择目录导入。
- 页面分别显示当前批次的上传字节进度和全部图片的处理进度、成功与失败数。首次使用检测器需等待模型加载；进度不会模拟增长。保持导入页面打开，点击“停止导入”可取消后续上传和当前后台任务，已保存图片保留。
- 预览自适应窗口，原始训练图片不压缩、不画框。审核列表按需生成最大 320 × 240 的缩略图，编辑画布仍加载原图。

文件传输完成后返回任务 ID，解码和入库不阻塞 HTTP。损坏图片单独计入失败，其他图片继续处理。`GET /api/tasks/{task_id}` 返回状态、总量、已处理数、成功数和失败数。取消保留已成功导入的样本。服务重启后，未完成任务标记为失败，可以重新提交；当前不自动断点续传。

## 视频导入

“数据采集”中选择“视频抽帧”，上传文件或填写服务器视频文件路径。选择“每 N 帧”或“每 N 秒”，点击“开始抽帧导入”。从首帧开始采样，原视频不会修改。

detection 可选预标检测器和自动标注类别。浏览器不支持的 AVI/MKV 编码可能无法直接预览，但后端仍可抽帧。按秒抽样需要有效视频帧率/时间戳；时间参数保存在每个样本的来源字段中。

## RTSP 采集

1. 在“摄像头”页添加名称、RTSP 地址、TCP/UDP，执行“连接测试”。
2. 在“数据采集”中选择目标数据集，勾选 1–9 个 RTSP 摄像头。画面按数量自动排列为单画面、两列或三列，桌面最多九宫格；窄屏自动减少列数。ROI 模式需要在每路画面上分别绘制 ROI。
3. 选择四种采集模式之一。ROI 模式先在画面上拖动绘制，可重画或清除。
4. 目标触发模式下，填写 **“触发目标名称或 ID”**，逗号分隔，命中任一目标即保存。再独立选择自动标注检测器和类别，设置保存间隔、置信度和去重阈值，点击“开始采集”。
5. 点击“停止”后，任务在当前推理或文件写入结束时停止。切换页面不终止后台采集。

去重条件：达到保存检查间隔、满足采集条件、pHash 与近期样本相似度低于阈值。相似度取 `1 - 汉明距离 / 64`，默认 `0.92`，越小越严格。重复计数只统计实际检查后跳过的候选图片。近期窗口跨启动从当前数据集最近 128 张图片恢复。

实时触发检测用于预览和采集判断；训练原图始终不画框。所有数据集类型均可填写触发目标，它独立于数据集类别。预标关闭时仍可采集无标签图片；raw/classification 不会把触发框写入标注。

例如采集含车辆的原始帧，同时标注 `person、play_phone、car`：

1. 在“类别 / 设置”中配置这三个类别，数据集 ID 可自行指定。
2. 采集模式选“检测到目标 · 完整原图”。触发检测器可选“自定义 YOLO”并指定 COCO 权重 `yolov8n.pt`，目标填 `2` 或 `car`。`2, 5, 7` 表示 COCO 权重的 car、bus、truck。
3. 在“保存后自动标注”中独立选择模型、勾选三类，并在每个类别下填写 **“检测类别 ID”**。例如使用 COCO 权重：`person` 填 `0`、`play_phone` 填 `67`、`car` 填 `2`；手机检测框会保存为数据集的 `play_phone`。触发和标注可以使用不同的 `.pt` 文件。即使使用同一检测器，也会分别按触发目标和标注映射推理，不会把触发框直接当成全部标注。
4. 保存完整原图后，写入所选类别的标注。目标裁剪模式则由触发框决定裁剪范围，再对裁剪图标注。

自定义 YOLO 的数字按其 **模型原始 names** 解释，请用“读取模型类别”确认；仅 COCO 模型使用 COCO 数字映射。YOLO-World 支持英文名称，数字按 YOLO 使用的 COCO 0–79 连续索引转换为名称（不是 COCO 原始 category_id）。标注映射可使用与检测类别不同的名称：`67 cell phone → play_phone` 保存的是手机本身的框，不会自动变成玩手机人员的框，审核时按实际标注要求调整。检测类别 ID 留空则继续按数据集类别名称匹配。

API：采集 `target_classes` 为名称或数字字符串列表，例如 `["2", "7"]`；`trigger_model_path` 指定触发权重，省略时兼容旧请求的 `model_path`；`model_path` 是标注权重。采集、图片导入、视频抽帧、已有图片预标均支持 `label_class_ids`（数据集 ID 列表）。省略 / null 表示全部，空列表或无效 ID 会拒绝。

每个标注类别的“检测类别 ID”支持填写多个值，用逗号分隔。例如 `car` 填 `2,3`，COCO 的汽车和摩托车检测框都会保存为同一个 `car` 类别。COCO 中 `1` 是自行车、`2` 是汽车、`3` 是摩托车，没有独立的电动车类别；应根据所用模型对电动车的实际输出选择 ID。审核页会记住多 ID 配置，之前保存的单 ID 配置也能继续使用。

上述四个标注入口均支持 `label_class_mapping`，键是保存用的数据集类别 ID，值是单个检测模型类别 ID 或非空 ID 数组。例如数据集为 `4 person、9 play_phone、12 car` 时，传 `{"label_class_ids":[4,9,12],"label_class_mapping":{"4":0,"9":67,"12":[2,3]}}`，也兼容原来的 `"12":2`。同一保存类别内重复的检测 ID 自动去重。未提供映射的类别按名称匹配；未勾选类别的映射不参与推理。不存在的源 ID、数据集类别或把同一检测目标映射到多个保存类别会明确报错。

每个画面显示连接状态、摄像头读取 FPS、保存数、预标数和重复跳过数，可“停止此路”；“停止本数据集全部”不会停止其他数据集。新增勾选的摄像头可继续启动，已有采集配置不受影响；刷新页面会恢复当前数据集正在运行的全部画面。单路启动失败时，其他已成功启动的摄像头继续采集，并显示失败原因。

预览 JPEG 最大宽度 960、质量 75，仅影响浏览器画面；采集快照与训练原图保持原始分辨率，ROI 仍使用原图坐标。单路预览每次请求完成后等待 150 ms，多路为 250 ms，5–9 路为 400 ms；页面隐藏时暂停预览请求，不停止后台采集。浏览器预览频率不等同于摄像头 FPS，断流后清空画面并重连。每路独立维护最近 128 张采集图片的去重窗口。

API：`POST /api/collection/start` 每次启动一路（`camera_id`），总上限 9 路；`GET /api/collection/status` 返回 `sessions`、`active_count` 和 `max_cameras`。`POST /api/collection/stop?camera_id=...` 停止指定摄像头，`?dataset_id=...` 停止指定数据集，不传筛选停止全部。检测预览用 `GET /api/collection/frame?camera_id=...`，多路时必须指定摄像头。

## 自动预标与人工审核

“标注审核”右侧的“已有图片自动标注”可选择 YOLO-World 或自定义 YOLO、一个或多个自动标注类别，处理当前图片或全部待审核图片。默认只处理 `pending`；图片已有所选类别的框时跳过，跳过项单独计数，不计为失败。只有其他类别标注的图片可以补标所选类别。

审核位置与选项会在当前浏览器中按数据集自动保存，无需手动点击保存。停在第 188 张时，切换页面、刷新或关闭后重新打开，会回到同一张图片并滚动到对应缩略图；同时恢复审核状态筛选、当前绘框类别，以及自动标注的模型、路径、置信度、覆盖选项、所选类别和检测 ID 映射。刷新也会恢复上次页面与数据集。

位置按图片唯一 ID 定位：前面的样本被删除后仍打开原来的图片，显示序号随列表变化；上次图片已删除或不符合筛选时，打开原位置附近的可用图片。当前筛选没有图片时显示空列表。临时网络错误不会清掉上次位置。记忆保存在浏览器本地，换浏览器、换访问地址或清除网站数据后不会继承；服务端图片和标注不受影响。

修改置信度后重标时，勾选 **“覆盖所选类别已有标注（重新预标）”**；仅替换所选类别的框（包括该类别的人工框），未检出时清空所选类别，其他类别保留。全选时替换全部框。API 对应 `overwrite=true`。不会覆盖推理期间发生的人工修改。

画布使用原图，并有限预加载相邻图片（最多缓存 6 张原图）；标注数据仍实时读取。不可变原图允许浏览器缓存，预览和缩略图用条件请求校验，未变化时返回 304。绘框、拖动、缩放、改类别和删除框都会立即保存 JSON、重新生成 preview，并将样本置为 pending；仅确认或拒绝时不再重新绘制图片，数据集统计在后台刷新，不阻塞切图。手工修改的框来源为 manual、置信度为空。最多撤销当前图片最近 50 次修改；切换图片清空撤销历史。

| 按键 | 操作 |
|---|---|
| A / ← | 上一张 |
| D / → | 下一张 |
| Enter | 确认并下一张 |
| Delete | 删除选中的框，保留图片 |
| N | 新增框 |
| 1–9 | 按类别按钮顺序切换类别，不改变类别 ID |
| Ctrl+Z / Cmd+Z | 撤销 |
| Esc | 取消绘制或选择 |

输入框、下拉框、文本框获得焦点时不触发这些快捷键。

classification 显示大图与类别按钮，选择类别后确认；未选择类别不能确认。raw 只浏览、管理、审核、删除和导出，无需框或分类标签。

“删除框”只修改标注。“删除样本”需二次确认，同步删除原图、JSON、preview、SQLite 记录并清理该数据集的已有导出快照，避免已删除的样本继续留在导出副本中。正在执行导入、预标、采集或导出时先停止任务再删除样本。

## 自定义 YOLO

在检测器中选择“自定义 YOLO”，填写服务器 `.pt` 路径，或选择 models 目录的候选文件。点击“读取模型类别”查看原始类别名称。只支持 Ultralytics 目标检测模型。

可在自动标注类别下填写**检测类别 ID**，明确将模型类别映射为所选数据集的 ID / 名称；留空则按名称精确匹配。例如模型 `67 cell phone` 可映射为数据集 `9 play_phone`，`0 person` 可映射为数据集 `4 person`。模型原始 names 不修改，保存用的数据集 ID 不必等于模型 ID。无效映射明确报错，未选类别不会保存。图片导入、视频、RTSP 和已有图片自动标注使用相同规则。

模型文件只读取，不改写，可用于目标触发、目标裁剪、视频预标、图片预标和实时预标。前端无需设置 GPU 编号。

## 数据导出

数据集页点“导出”。默认只导出 approved，不包含 rejected；可明确勾选“包含待审核”。检测、分类和 raw 数据集均支持三种方式：

- **不划分（整份导出）**：全部图片导出到同一份目录，至少需要 1 张图片。
- **训练集 + 验证集**：默认 80% / 20%，至少需要 2 张图片。
- **训练集 + 验证集 + 测试集**：默认 70% / 20% / 10%，至少需要 3 张图片。

各组比例可独立修改，支持小数，合计必须为 100%，每组大于 0%。弹窗按当前审核状态显示预计导出总数和每组张数；数量不足时会提示。生成后下载 ZIP，也可直接使用 exports 下的目录。

检测、分类数据集可在 **“训练 / 导出类别”** 勾选一个或任意多个类别。导出按数据集类别顺序从 0 连续编号，界面展示原 ID → 导出 ID。例如只选 `12 car`，导出的标签为 `0`、data.yaml 为 `0: car`，可训练单类别模型。检测数据集默认保留不含所选目标的图片作为空标签背景样本，可取消该选项仅保留含所选目标的图片；分类只导出属于所选类别的图片。预计张数与实际导出使用相同筛选条件。

导出的 TXT、JSON 和 dataset.json 类别编号保持一致，manifest.json 记录 `source_classes` 和 `class_id_mapping`。原数据集和原始标注不修改。平台负责训练数据准备与导出，实际模型训练仍通过外部训练工具执行。

目标检测导出：

```text
exports/yolo_时间_编号/
├── images/train/、images/val/、images/test/   test 仅在三份划分时生成
├── labels/train/、labels/val/、labels/test/
├── data.yaml
├── annotations/           JSON 快照
├── dataset.json
└── manifest.json          样本、划分、类别及来源配置
```

标签为 `class_id x_center y_center width height`，坐标归一化到 0–1。空目标图片生成空 txt。按图片随机划分，使用固定种子 42，API 可修改 seed；样本不变、比例和种子相同时划分可重复。按最大余数分配取整差额，并确保启用的分组至少有一张图片，各组不重叠、不遗漏。manifest 记录划分方式、请求比例、实际张数及每张图片归属。

界面导出使用从 0 开始的连续类别 ID；旧 API 请求未传 `class_ids` 时保留原 ID，空缺仍用 `__unused_class_ID` 占位。划分导出的 data.yaml 包含 train、val 和可选 test 路径，可由 Ultralytics 直接读取：

```bash
yolo detect train model=yolov8n.pt data=/绝对路径/exports/yolo_xxx/data.yaml
```

不划分时，检测导出到 `images/`、`labels/`，data.yaml 的 train 指向 `images`，val 留空；用于训练前需另行配置独立验证集。分类整份导出到 `images/类别ID_类别名/`，划分时使用 `train/类别ID_类别名/`、`val/类别ID_类别名/` 及可选 `test/类别ID_类别名/`。raw 导出到 `images/` 或 `images/train/`、`images/val/`、`images/test/`。所有方式均附统一 JSON 快照，ZIP 与解压目录一致。

API：`POST /api/datasets/{id}/export/preview` 预览张数，`POST /api/datasets/{id}/export/yolo`（检测）或 `/export` 生成后台任务。参数 `split_mode` 为 `none`、`train_val`、`train_val_test`；划分比例用 0–1 数值。例如三份划分：`{"split_mode":"train_val_test","train_ratio":0.7,"val_ratio":0.2,"test_ratio":0.1}`。不传 split_mode 时沿用默认训练/验证划分；none 忽略比例。

导出可传 `class_ids: [12]` 选择并重编号类别，`include_empty: false` 排除没有所选目标的检测图片。省略 / null 的 `class_ids` 保持旧行为，显式空列表或无效 ID 会拒绝。

## 常见问题

- **页面显示服务未连接**：执行 `bash start.sh status` 检查前后端及代理状态，通过 `http://服务器IP:5180/api/health` 检查是否返回 `status=ok`，并查看 `config/logs/backend.log`。网页和 API 都使用 5180，后端通过本机 socket 通信。
- **RTSP 无法连接或断流**：检查地址、账号、服务器到摄像头的网络和 RTSP 端口；默认 TCP；连接/读取超时约 5 秒，失败后约 2 秒重连。预览停止访问 90 秒后自动释放空闲读流。
- **CUDA 异常**：检查 `nvidia-smi` 和 PyTorch CUDA 支持；当前服务器驱动不可用时使用 `DEVICE=cpu`。切换设备后重启后端。
- **YOLO-World 加载失败**：检查权重存在、CLIP 依赖安装和首次下载网络；查看后台任务错误与后端日志。离线服务器需预先准备两个权重。
- **模型检测结果不符合预期**：预标是待审核建议；调整英文提示词与置信度，再人工确认。业务专用类别可使用自定义检测模型。
- **类别配置错误**：ID 与名称必须唯一；对象类别必须存在；raw 不允许类别，classification 不允许 bbox。
- **图片/视频读取失败**：检查文件内容、扩展名及编码；失败原因记录在任务中。视频中途解码中断会使任务失败，已保存样本保留。
- **图片或预览保存失败**：检查 datasets、config 的权限和剩余空间；文件通过临时文件 + 原子替换保存，异常会写后端日志。
- **并发修改冲突**：重新打开图片获取最新标注版本。不要启用多个 Uvicorn worker 或同时运行两个后端操作同一数据目录。
- **数据库/文件备份**：停止后端后一起备份 datasets 和 config/index.sqlite3；运行中备份应使用 SQLite backup API 或完整快照。
- **任务完成但有失败计数**：检查任务最后一条错误。损坏图片不影响其他图片处理；已有标注默认跳过并在任务里给出原因。
